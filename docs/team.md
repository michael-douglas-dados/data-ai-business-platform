# Time do portfólio pessoal

Este time trabalha exclusivamente no portfólio pessoal de Michael Douglas e na plataforma Customer Data Workbench. As tarefas, arquivos e evidências pertencem a este projeto.

Michael define os objetivos, prioriza os recortes de negócio e revisa a apresentação pública. O desenvolvimento utiliza agentes de IA para implementação, pesquisa, revisão e testes, com acompanhamento do agente responsável pela integração.

## Papéis e entregas

| Papel | Responsabilidade | Entrega verificável |
| --- | --- | --- |
| Integração | Organizar os vinte projetos, manter os contratos entre frontend e API e consolidar a entrega. | Catálogo, instruções de execução e verificação integrada. |
| Frontend e experiência de uso | Implementar o CRM e as telas de análise em React e TypeScript. | Interface funcional, build e revisão de estados de erro, vazio e carregamento. |
| Dados e backend | Implementar ingestão, regras de negócio, persistência e APIs. | Contratos, regras documentadas e testes de comportamento. |
| Qualidade e segurança | Investigar regressões, consistência, concorrência e exposição de informação. | Achados com evidências e confirmação das correções. |
| Pesquisa e curadoria | Consultar vagas e fontes técnicas, verificar pertinência e registrar limites. | Pesquisa datada, links primários e justificativa da escolha de ferramentas. |

## Critérios de trabalho

- Cada tarefa possui um conjunto de arquivos sob responsabilidade de seu executor. Mudanças que afetam outro componente são comunicadas ao responsável pela integração.
- Uma tecnologia é apresentada como utilizada quando aparece em código executável. A indicação de teste exige o registro da verificação realizada.
- Os projetos descrevem os dados de demonstração, o objetivo do negócio, os comandos de execução e os limites conhecidos.
- A revisão verifica comportamento em reexecução, entradas inválidas, falhas parciais e concorrência quando esses cenários se aplicam à função.
- Publicações usam dados sintéticos ou fontes públicas identificadas. Credenciais e configurações privadas ficam fora dos arquivos publicados.
- Referências externas recebem atribuição. Métricas de demonstração são apresentadas com o conjunto de dados e o método usados para calculá-las.

## Autoria e escopo

Michael Douglas é o responsável pelo portfólio e pela direção dos casos de negócio. O código e a documentação foram desenvolvidos com assistência de IA. Cada entrega pública deve declarar seu estado de execução e revisão.

Os critérios gerais de pesquisa e curadoria foram adaptados de práticas de agentes já utilizados pelo autor, como preferência por fontes primárias, avaliação de pertinência e verificação de manutenção. A organização deste time é própria do portfólio pessoal.

## Revisão de uma entrega

1. Conferir o problema e os critérios de aceite do caso.
2. Executar o fluxo documentado com a base de demonstração.
3. Verificar os testes que cobrem as regras e falhas relevantes.
4. Revisar a correspondência entre documentação, código e resultados.
5. Conferir os arquivos preparados para publicação.
6. Registrar limitações e resultados da validação.

A atividade dos agentes neste projeto é registrada pela colaboração da sessão e pelos arquivos entregues. Este documento descreve os papéis do time e seus critérios de trabalho.
